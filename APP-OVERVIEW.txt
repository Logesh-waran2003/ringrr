# APP-OVERVIEW.md — Ringrr (Nudge)

## 1. What This App Does

Ringrr (internally "Nudge") is a mobile reminder/alarm app that lets users schedule one-time reminders with categories, custom sounds, and conflict detection. When a reminder fires, a fullscreen alarm screen appears with snooze/dismiss options. Completed and dismissed reminders are tracked in a history view with completion-rate stats.

## 4. How the App Starts Up

1. **Entry**: `package.json` → `"main": "expo-router/entry"` boots expo-router.
2. **Root Layout** (`src/app/_layout.tsx`):
   - Wraps everything in `GestureHandlerRootView`
   - Sets `StatusBar` to light (white icons on dark bg)
   - Calls `setupNotificationChannels()` — creates Android notification channels (MAX importance alarm channel with DND bypass, HIGH importance early-alert channel)
   - Calls `requestNotificationPermission()` — requests OS notification permission
   - Invokes `useNotificationHandler()` hook — sets foreground notification display policy + registers tap handler that navigates to `/alarm?id=<reminderId>`
   - Configures Stack navigator with screens: index, (tabs), create (modal), edit (modal), alarm (fullscreen modal)
3. **Index** (`src/app/index.tsx`): Immediately redirects to `/(tabs)` via `<Redirect>`
4. **Tabs Layout** (`src/app/(tabs)/_layout.tsx`): Renders `<Tabs>` with custom `TabBar` component, two screens: index (Home) and history
5. **useReminders hook** (called on first screen mount): Loads all reminders from AsyncStorage, re-registers all pending notifications (cancels all first, reschedules future ones), updates state with new notification IDs

## 6. Core User Flows

### Flow 1: Creating a Reminder

1. **User taps FAB** (center "+" button in TabBar) → `TabBar.tsx` calls `router.push('/create')`
2. **Create screen appears** (slide from bottom modal) → `src/app/create.tsx`
3. **User fills form**: title (autoFocus, 34px teal text), selects category dots, taps TIME/DATE cards to open native DateTimePicker
4. **Conflict detection** runs via `useEffect` → `detectConflicts()` in `src/services/conflictDetection.ts` checks if any pending reminder is within ±5 minutes
5. **If conflict**: orange warning banner appears showing conflicting reminder names/times
6. **User taps "Set Reminder"**: `handleSave()` → if conflicts exist, shows Alert with "Add Anyway" / "Reschedule" options
7. **doSave()**: creates `Reminder` object with `generateId()`, calls `addReminder()` from `useReminders` hook
8. **Hook's addReminder**: requests permission → calls `scheduleReminderNotifications()` (schedules main notification + 5-min early alert) → calls `storageAdd()` (appends to AsyncStorage) → updates state
9. **Success haptic** fires → `router.back()` dismisses modal

### Flow 2: Alarm Firing and Dismissal

1. **Notification fires** at `scheduledAt` time via expo-notifications (Android: MAX importance channel, bypasses DND)
2. **User taps notification** → `useNotificationHandler.ts` listener fires → `router.push('/alarm', { id })` 
3. **Alarm screen renders** (`src/app/alarm.tsx`): loads reminder from AsyncStorage, displays fullscreen dark-teal UI with pulsing bell icon, large time, reminder card
4. **User taps "Snooze 5 min"**: `handleSnooze()` schedules a new notification 5 minutes from now, navigates back
5. **User taps "✕ Dismiss"**: `handleDismiss()` → `markDismissed(id)` → updates reminder status to 'dismissed', cancels notifications, saves to storage, navigates back
6. **Reminder now appears in History** tab with "Dismissed" pill

### Flow 3: Editing and Completing a Reminder

1. **User taps a timeline card** on Home → `router.push('/edit', { id })`
2. **Edit screen** (`src/app/edit.tsx`) loads, finds reminder by ID, populates all fields
3. **User modifies** title/date/time/category/sound/note
4. **On save**: cancels old notifications → schedules new ones → updates storage → navigates back
5. **Alternatively**: user taps checkmark icon on Home timeline card → `markComplete(id)` → status changes to 'completed' → card disappears from timeline, appears in History

## 7. Data Model / Storage

### Reminder Interface (`src/types/reminder.ts`)

```typescript
interface Reminder {
  id: string                    // Generated: `${Date.now()}-${random7chars}`
  title: string                 // Max 100 chars
  description?: string          // Optional note, max 500 chars
  scheduledAt: string           // ISO timestamp
  sound: SoundOption            // { type: 'builtin', name } | { type: 'custom', uri, fileName, duration }
  status: ReminderStatus        // 'pending' | 'completed' | 'dismissed'
  category: Category            // 'Personal' | 'Work' | 'Health' | 'Social'
  createdAt: string             // ISO timestamp
  notificationId?: string       // OS notification ID for main alarm
  earlyNotificationId?: string  // OS notification ID for 5-min early alert
}
```

### Storage Mechanism (`src/services/storage.ts`)

- **Engine**: `@react-native-async-storage/async-storage`
- **Key**: `nudge:reminders:v2`
- **Format**: JSON array of all Reminder objects (no pagination, no indexing)
- **Operations**: Load all → filter/modify in memory → save entire array back
- **No migration logic** from v1 to v2 visible

## 8. Auth

**None.** The app is fully local/offline with no user accounts, no backend, no API calls. All data lives in AsyncStorage on-device.

## 11. Design Inconsistencies & Pain Points

### Inconsistencies

| Issue | Where | Details |
|-------|-------|---------|
| **CTA button radius mismatch** | Create vs Edit | Create uses `borderRadius: 999` (pill). Edit uses `borderRadius: 16` (rounded rect). Same semantic action, different shape. |
| **Card background inconsistency** | History tab vs History standalone | Tab version uses `surfaceElevated` (#1C1E2A). Standalone uses `surface` (#161820). Same content, different elevation. |
| **Dot size inconsistency** | History tab vs History standalone | Tab: 8px dot. Standalone: 10px dot. |
| **Header style mismatch** | Edit vs Create | Create: "New Reminder" centered, 17px 700 weight, white. Edit: "Edit reminder" centered, 17px 500 weight, secondary color. Different weights and colors for same-level headers. |
| **Category display varies wildly** | Across screens | Home: left accent bar only (no text). Create: dot + text row. Edit: pill buttons with borders. ReminderCard: accent bar only. History: dot only. No consistent pattern. |
| **CATEGORY_COLORS duplicated 6+ times** | Every file that shows categories | Same color map hardcoded in: (tabs)/index, (tabs)/history, create, edit, alarm (partially — uses repeat icon??), history standalone, reminders/index, ReminderCard, CategoryBadge, UpcomingPanel. Should be in theme.ts. |
| **Save button text color** | Create vs Edit | Create: `#0D0E16` (bg color). Edit: `#000` (pure black). Very close but technically different. |
| **Sound pill active state** | Create vs Edit | Create: teal border 1.5px, surfaceElevated bg, teal text. Edit: solid teal bg, teal border, black text + music note icon. Completely different active treatment. |
| **Close/back button style** | Create vs Edit | Create: plain arrow icon. Edit: circular surface-colored button with X icon. Different patterns for same "go back" action. |
| **Unused components** | CategoryBadge, UpcomingPanel, DateTimePicker | Built but never imported into any active screen. Dead code / leftover from iteration. |
| **Duplicate History screens** | `(tabs)/history.tsx` vs `/history.tsx` | Two history implementations with different styling. Tab version is richer (summary card, pills). Standalone is simpler. |

### Pain Points

| Issue | Severity | Details |
|-------|----------|---------|
| **No search or filter** | Medium | With many reminders, no way to find a specific one. Timeline is the only view. |
| **Donut ring is fake** | Low | The "progress ring" is just a full-border circle — it doesn't actually animate to show partial completion. Always shows a complete ring with percentage text inside. |
| **Menu button does nothing** | Low | Hamburger icon in top bar has no onPress handler — purely decorative. |
| **"VIEW ALL" does nothing** | Low | The "VIEW ALL" text in section header has no navigation action. |
| **Avatar placeholder** | Low | Person icon (Home) and teal-bordered circle (Create) are non-functional — no profile/settings screen exists. |
| **"High Priority" is meaningless** | Low | Text below Create CTA says "• High Priority" but there's no priority system — all reminders are equal. |
| **No delete confirmation from Home** | Medium | Timeline cards on Home have only a checkmark (complete) — no swipe-to-delete or long-press. Must go to Edit to delete. The reminders/index view has swipe-to-delete but Home doesn't. |
| **Tiny touch targets** | Medium | History delete button (trash icon 15px with only 2px padding) relies on hitSlop={10} for accessibility. Checkmark buttons similarly small. |
| **No pull-to-refresh** | Low | ScrollView with no RefreshControl — user must navigate away and back to refresh. |
| **Contrast concern on muted text** | Medium | `textMuted` (#5A5B6E) on `bg` (#0D0E16) has approximately 3.5:1 contrast ratio — below WCAG AA (4.5:1) for body text. Section labels, timestamps, and placeholders may be hard to read. |
| **Sound "Preview" does nothing** | Low | "Preview Sound" link in Create screen has onPress that only fires haptic, no actual audio playback. |
| **Frequency is hard-coded "Once"** | Low | Displayed as if configurable but there's no repeat/recurrence system. |

## 12. Things Worth Knowing / Rough Edges (Functional)

1. **App is named "Nudge" internally** but repo is "ringrr" and brand text says "Ringr" — identity is split three ways.

2. **Notification re-registration on every app open**: `useReminders` hook cancels ALL scheduled notifications and re-schedules them from storage every time the app launches or comes to foreground. This is safe but wasteful for many reminders.

3. **No data backup/export**: All data is in AsyncStorage only. Uninstalling the app loses everything.

4. **Test alarm feature built-in**: Home screen has a visible "Test" button that schedules a notification in 5 seconds and navigates to alarm screen. This appears to be a dev tool left in the production UI.

5. **Two competing home screens**: The `(tabs)/index.tsx` (dashboard with donut) and `reminders/index.tsx` (grouped list) are both full implementations. The app currently routes to the dashboard, but the reminders list is a complete alternative that's reachable via `/reminders` route.

6. **Snooze doesn't track state**: Snoozing just schedules a new raw notification — it doesn't update the reminder's `scheduledAt` or status. The snoozed notification's tap will try to load the reminder from storage again.

7. **Custom sound support is declared but unused**: The `SoundOption` type supports `{ type: 'custom', uri, fileName, duration }` and `expo-document-picker` is in dependencies, but no UI exists to upload custom sounds.

8. **No error boundary**: If AsyncStorage corrupts or fails, the app shows nothing (loading state returns null). No fallback UI.

9. **Alarm screen loads from storage independently**: Instead of receiving the reminder via params/context, it re-reads ALL reminders from AsyncStorage and finds by ID. This means if the reminder was deleted between notification scheduling and tapping, the screen silently navigates back.

10. **Web support is partial**: `global.css` and `react-native-web` are present, and `app.json` has web output config, but the notification/alarm system is mobile-only. The tab icons reference image assets that may not render on web.
